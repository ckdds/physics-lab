오늘의 학습 목표

관찰과 예측

게임 속 캐릭터는 컴퓨터마다 같은 빠르기로 움직여야 합니다. 그런데 어떤 컴퓨터는 1초에 화면을 60번, 어떤 컴퓨터는 144번, 느린 컴퓨터는 30번만 다시 그립니다. 그래도 공이 똑같은 빠르기로 움직이게 하려면 어떻게 해야 할까요?

아래 실험실에는 공 두 개가 있습니다. 파란 공은 “흐른 시간만큼” 움직이고, 주황 공은 “화면을 한 번 그릴 때마다 같은 거리만큼” 움직입니다. 실험실을 실행하기 전에 먼저 예측해 보세요.

예측 질문

  1. 가상 프레임률을 30회/s로 낮추면 두 공 중 어느 공이 뒤처질까요? 그 이유는 무엇일까요?
  2. 속도가 120 px/s일 때 5초가 지나면 파란 공은 몇 px 이동했을까요?

핵심 물리 개념

① Canvas 좌표계

왼쪽 위가 (0, 0)입니다. x는 오른쪽으로, y는 아래쪽으로 커집니다.

수학 시간의 그래프는 y가 위로 커지므로 방향이 반대입니다.

② 게임 루프

requestAnimationFrame은 “다음에 화면을 그릴 때 이 함수를 불러 줘”라는 예약입니다. 함수 안에서 다시 예약하면 루프가 계속 돕니다.

③ deltaTime (dt)

지난 프레임 이후 흐른 시간입니다. 브라우저는 시각을 밀리초(ms)로 알려 주므로 1000으로 나누어 초(s)로 바꿉니다.

dt = (지금 시각 − 이전 시각) ÷ 1000

1초에 60번 그리면 dt ≈ 0.0167초, 30번 그리면 dt ≈ 0.0333초입니다.

속도와 위치의 관계

속도는 “1초 동안 위치가 얼마나 바뀌는가”입니다. 그러므로 dt초 동안에는 속도 × dt만큼 움직입니다.

새 위치 = 현재 위치 + 속도 × dt   →   x += speed * dt

예) 속도 120 px/s, dt = 0.0167 s → 한 프레임에 약 2 px 이동 → 1초(60프레임) 동안 약 120 px 이동. 프레임이 30번뿐이면 dt가 두 배(0.0333 s)라서 한 번에 약 4 px씩 움직이고, 1초 뒤 위치는 같습니다.

이 실험의 가정과 단순화

  • px는 화면 단위입니다. 실제 미터(m)와 같지 않습니다. 실험실의 화면은 항상 가로 800 px × 세로 450 px로 계산합니다.
  • dt는 최대 0.05초로 제한합니다. 탭을 바꿨다 돌아오면 그동안의 시간은 더하지 않습니다.
  • 공은 오른쪽 끝을 벗어나면 왼쪽에서 다시 나타납니다(벽 충돌은 4주차에 배웁니다).

중요한 줄

  • speed * dt: “1초에 speed px”를 “dt초 동안의 거리”로 바꿉니다.
  • speed / 60: 화면을 1초에 60번 그린다고 가정합니다. 가정이 틀리면 빠르기가 달라집니다.
  • 오른쪽 끝을 벗어나는지 검사할 때 반지름 RADIUS를 빼서, 공이 완전히 사라진 뒤에 옮깁니다.

값을 바꾸면?

  • speed를 2배로 → 같은 시간에 2배 멀리 갑니다(두 공 모두).
  • 프레임률 30회/s → 파란 공은 그대로, 주황 공은 절반 빠르기가 됩니다.
  • * dt를 지우면 → 한 프레임에 120 px씩 움직여 공이 순식간에 사라집니다. 단위가 맞지 않기 때문입니다.
